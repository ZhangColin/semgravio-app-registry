# semgravio-app-registry 部署文档（单服务内网接入方形态）

> 口径：一台已由 semgravio-infra 起好共享基础设施（`semgravio-{pg,redis,nginx}` + `webnet`）
> 的服务器（eu-1），把本服务从零发布到日常运维的全部操作。
> 形态：本服务是共享基础设施的**普通接入方**（与 aiplatform 同款机制、同一套使用习惯），只加入
> webnet、容器名 `semgravio-app-registry`、容器端口 8088，**不映射宿主端口、不装 nginx 公网路由、
> 不配 SSL——只对内可达**（ApiKey bootstrap 端点返回明文 apiSecret，网络边界即信任边界，见
> CONTEXT.md「bootstrap 端点加固：网络隔离」）。
> 命令全部在开发机仓库根执行（Mac / Windows Git Bash 通用；PowerShell 里 `bash deploy/...`）。
> 本档由本地端到端排练 `deploy/rehearsal.sh`（#31，§11）收口；机制与 aiplatform deploy 同源、
> 该侧已在 eu-1 实跑验证，本服务真实服务器首次发布由维护者按本档执行。

## 1. 前置条件

1. **开发机**：本仓完整 checkout + JDK 21 + Maven——fat jar 只能在开发机构建（私有 cartisan-boot
   父 POM 只在开发机 `~/.m2`，未发布远端），服务器只做 Docker 镜像构建；跑本地排练（§11）还需 Docker。
2. **服务器**：共享 infra 已起栈且 healthy（`semgravio-pg` / `semgravio-redis` / `semgravio-nginx`
   ＋ `webnet`）。infra 归 semgravio-infra 管，本服务不代起栈——缺失/不健康时发布会在门禁处
   非零停下并提示先起 infra。
3. **SSH 私钥**可登录服务器（默认 `$HOME/ssh/semgravio-eu-1.pem`，可 `SSH_KEY=...` 覆盖）。
   发布全程只用私钥（BatchMode + ConnectTimeout），不用密码、不关主机密钥校验。
4. 不需要：域名、SSL 证书、宿主端口规划、nginx 路由——内网 only 形态一概用不上（§7）。

## 2. 首次发布与重复发布（同一入口）

```bash
deploy/release.sh        # 打包 → scp → infra 门禁 → env 首次自动准备/全量校验 → 发布前备份
                          # → 解包 → compose up -d --build（不先 down）→ 健康验收 → 凭证反馈
```

打包细节（脏工作区默认拒绝、`ALLOW_DIRTY=1` 逃生开关、部署包恒 LF）见 `deploy/build-bundle.sh`
头注释；发布输出带 `REVISION`（当前上线 commit），可追溯线上产物出处。

### 2.1 首次发布（服务器应用目录还没有 `.env.production`）

release 自动准备的是**启动前配置**；应用内初始化一律由应用自己完成——

| 阶段 | 谁做 | 做什么 |
|---|---|---|
| 启动前配置 | release.sh（仅首次） | 经共享 infra `ensure-db-user` 契约幂等建独立库 `semgravio_app_registry` ＋ 同名低权限角色（不经手 PG 超管密码）；从 infra 凭据正本取 Redis 密码；生成库密码与 AES master key；落服务器 `.env.production`（600） |
| 表结构 | Flyway（应用启动） | 建 `ar_*` 三表 ＋ 独立 history 表，版本化演进（库本身由上一行的 ensure-db-user 建） |
| 预置数据 | 平台 seed（应用启动） | 建 admin-console 应用 ＋ ApiKey；首次创建或主密钥轮换时在日志出一次性明文 apiSecret |

部署脚本不写任何业务 SQL、不复制 seed 逻辑——**没有第二个初始化入口**；应用升级、重装容器、
换服务器都只靠 Flyway ＋ 平台 seed 自愈，不存在「忘了跑初始化脚本」这一类故障。

首次发布收尾看两样东西：

- `★ admin-console ApiKey 首次创建`：把 `apiKey = admin-console`（＝appCode＝请求头 `X-App-Id`）
  与一次性显示的 `apiSecret` 配进 admin-console 的签名客户端（HMAC 验签）；
- master key：立即存入密码管理器（§4）。

### 2.2 重复发布

- env 与全部凭据终身复用：master key 绝不重生成、不被部署包覆盖（包内无 `.env*`，现网 env 不动）；
- 每次发布全量校验 env（必需变量非空、master key 为 Base64 且解码恰好 32 字节），失败在应用
  变更前非零退出，且**绝不会**自动换 master key「修复」；
- 每次发布前自动备份当前数据库（§8）；无凭证事件时输出「无新凭证事件（seed 幂等跳过）」。

### 2.3 admin-console 凭证接收

- 明文 `apiSecret` 只在发布终端显示一次（库里只存 AES-GCM 密文），不落 Git/部署包/服务器任何文件；
- 事件两种：**created**（首次创建，首次发布或库被清空后）与 **rotated**（master key 变更后 seed
  自动轮换）——rotated 时旧值作废，须立即更新 admin-console 配置；
- 健康探活可能早于 seed 落日志（窄窗）：看到「无新凭证事件」但确属首次发布时，稍候自查——
  日志仍保留时再次查看 seed 凭证事件：

  ```bash
  deploy/server.sh logs | grep 'admin-console seed'
  # 等价服务器侧命令：docker logs semgravio-app-registry 2>&1 | grep 'admin-console seed'
  ```

- 日志轮转为 json-file 10m×3，超出即丢。错过日志**不用轮换凭证**——bootstrap 端点随时可取回
  admin-console 的 apiSecret（§6/§10）。

## 3. 参数覆盖与常用开关（与 aiplatform 同一套）

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVER_HOST` | 3.70.172.160 | 服务器（eu-1） |
| `SERVER_USER` | ubuntu | SSH 账号 |
| `SSH_KEY` | `$HOME/ssh/semgravio-eu-1.pem` | SSH 私钥 |
| `REMOTE_DIR` | semgravio-app-registry | 服务器应用目录（相对 `$HOME`；绝对路径以 `/` 开头也可） |
| `INFRA_DIR` | semgravio-infra | 共享 infra 单元目录（`ensure-db-user` 与凭据正本所在） |
| `HEALTH_WAIT_SECONDS` | 180 | 健康验收上限（Flyway 首启迁移慢可调大） |

常用开关：

- `SKIP_BUILD=1`：跳过打包，复用 `dist/` 最新部署包只发布；
- `ALLOW_DIRTY=1`：工作区脏仍打包（明确警告：源码树按 HEAD、jar 按工作区，两者可能不一致）；
- `SKIP_BACKUP=1`：显式跳过发布前备份（自担风险）。

```bash
SERVER_HOST=1.2.3.4 SSH_KEY=~/ssh/other.pem deploy/release.sh    # 覆盖连接参数
SKIP_BUILD=1 deploy/release.sh                                    # 复用现包快发布
```

## 4. master key（最重要的一个值）

- `APP_REGISTRY_API_SECRET_MASTER_KEY`：Base64 的 32 字节 AES-256 主密钥，首次发布自动生成，
  此后**终身不变**——库里每一条 apiSecret 密文都靠它解（#26 决策 10）；
- 必须立即存入**密码管理器**或同等**离线备份**：它只存在于服务器 `.env.production`（600）。
  **数据库备份不含 master key**（pg_dump 只有库内数据，apiSecret 在库里也只是 AES-GCM 密文）——
  服务器盘坏且无离线备份 ＝ 全部 apiSecret 永久不可解，只能逐一重建凭证；
- 真换了 master key：下次启动 seed 自动轮换 admin-console 的 apiSecret 并在发布尾部反馈（§2.3），
  其他应用的 ApiKey 需逐一重建；
- 三类 secret（master key / 库密码 / Redis 密码）一律不进发布终端输出、不进 Git/部署包/上传归档。

## 5. 内部服务怎么调用本服务（identity / admin-console / 其他 provider 服务）

- **base URL（同 webnet 服务）**：`http://semgravio-app-registry:8088`——webnet 容器 DNS 直达，
  **无需服务器 IP 或宿主端口**；
- **`localhost` 指向调用方容器自身**：除本服务自己容器外，任何地方写
  `http://localhost:8088` 都打不到本服务；宿主机进程和 webnet 外容器不能直接使用容器 DNS
  （要么把调用方加入 webnet，要么经已入网的服务转发），也不存在「宿主端口映射」这条退路（§7）；
- 探活：容器内 `/actuator/health`（compose 健康检查同源，`deploy/server.sh smoke` 即它）。

## 6. 端点清单与签名要求（均挂在 base URL 下）

**bootstrap 端点**（机机验签起点 / 逃生舱；加固＝内网隔离，见 §7）：

| 方法 | 路径 | 用途 | 签名要求 |
|---|---|---|---|
| GET | `/api/app-registry/api-keys/{apiKey}` | ApiKey bootstrap：按 apiKey 取回 apiSecret 明文（`RemoteApiKeyProvider` 契约；master key 轮换后的逃生舱，也是错过日志后取回凭证的入口 §2.3） | **无验签**（`@NoSignature`——唯一不验签的端点，死锁逃生舱） |
| GET | `/api/app-registry/sso-clients/{clientId}` | SSO client bootstrap：identity 拉取 client 元数据（含 client_secret 的 hash，不含明文） | 需验签（`@RequireSignature`——identity 预持凭证，无死锁） |

**管理 API**（由 admin-console 签名调用；错误码契约见各控制器 `@ErrorCodes`/swagger）：

| 方法 | 路径 | 用途 | 签名要求 |
|---|---|---|---|
| POST | `/api/app-registry/apps` | 创建应用（appCode 创建后不可改） | 需验签 |
| GET | `/api/app-registry/apps` | 应用分页列表 | 需验签 |
| GET | `/api/app-registry/apps/{id}` | 应用详情 | 需验签 |
| PUT | `/api/app-registry/apps/{id}` | 更新应用基本信息 | 需验签 |
| PUT | `/api/app-registry/apps/{id}/disable` | 禁用应用（admin-console 不可禁用） | 需验签 |
| PUT | `/api/app-registry/apps/{id}/enable` | 启用应用 | 需验签 |
| POST | `/api/app-registry/apps/{appId}/api-keys` | 创建/轮换 ApiKey（响应一次性返明文 apiSecret） | 需验签 |
| GET | `/api/app-registry/apps/{appId}/api-keys` | 查询应用的 ApiKey（不返明文） | 需验签 |
| PUT | `/api/app-registry/apps/{appId}/api-keys/disable` | 禁用 ApiKey（admin-console 的不可禁用） | 需验签 |
| PUT | `/api/app-registry/apps/{appId}/api-keys/enable` | 启用 ApiKey | 需验签 |
| POST | `/api/app-registry/apps/{appId}/sso-clients/credentials` | 创建（无则建）/重置（有则只换 secret）凭证，明文 client_secret 仅返一次 | 需验签 |
| PUT | `/api/app-registry/apps/{appId}/sso-clients` | 整份替换 SSO 配置（redirect_uris 等，不动凭证） | 需验签 |
| GET | `/api/app-registry/apps/{appId}/sso-clients` | 查询 SsoClient（不返明文） | 需验签 |
| PUT | `/api/app-registry/apps/{appId}/sso-clients/disable` | 禁用 SsoClient | 需验签 |
| PUT | `/api/app-registry/apps/{appId}/sso-clients/enable` | 启用 SsoClient | 需验签 |

## 7. 网络边界现状（内网 only）与未来外部调用

- **现状**：无宿主端口（compose 不写 `ports`）、无 nginx 公网路由、无需 SSL。同 webnet 服务经
  容器 DNS 访问（§5）；安全组/防火墙不用为本服务开任何端口。
- **为什么**：ApiKey bootstrap 端点无验签且返回明文 apiSecret，公网直接暴露即凭证泄漏——
  网络边界即信任边界，本服务自身不再叠鉴权（CONTEXT.md）。
- **未来确有外部调用方时须另行设计**：经共享 nginx 的门禁装路由 ＋ SSL（参照 aiplatform
  部署文档「转正式切换点」一节），且**不能直接公开**返回明文 apiSecret 的匿名 bootstrap 端点——
  bootstrap 保持仅内网，外部流量只走带验签的接口面。

## 8. 备份

- **自动**：每次发布前（应用变更前）用本服务自己的低权限角色 ＋ env 正本库密码 pg_dump 独立库
  `semgravio_app_registry`，落服务器应用目录 `backups/semgravio_app_registry-<时间戳>.sql.gz`
  （600；先写 `.tmp` 校验完整再转正名，失败即中止发布、不留残缺文件）；
- **手工**：`deploy/server.sh dump`（与发布前备份同一数据库边界与凭据，不经手 PG 超管，不碰
  其他服务的库）；
- **备份不等于回滚**：当前**不支持自动应用/数据库回滚**——恢复是人工动作（把备份导回库 ／
  用旧 REVISION 重发布）；发布形态为重建容器，也**不承诺零停机**；
- 备份不含 master key（§4）；当前备份留在服务器盘上，转正式时可考虑异地/对象存储（待办）。

## 9. 日常运维（deploy/server.sh）

```bash
deploy/server.sh status        # 容器概览（本服务 ＋ 共享 semgravio-{pg,redis,nginx}）
deploy/server.sh logs [svc]    # 跟日志：app（缺省）/ pg / redis / nginx
deploy/server.sh restart       # 只重启本服务容器（不重建镜像；不动共享 infra）
deploy/server.sh dump          # 手工备份（与发布前备份同边界）
deploy/server.sh smoke         # 容器内 actuator/health 冒烟（不碰返回明文的 bootstrap 端点）
deploy/server.sh sh            # 登服务器交互 shell
```

换版上线（打包＋发布＋发布前自动备份＋重建）不是这里——`deploy/release.sh`。
停机：服务器上 `docker compose -f docker-compose.prod.yml down`（不删数据；共享 infra 不动）。
日志：`deploy/server.sh logs`（Flyway 迁移、seed 凭证事件、验签失败都在应用日志里）。

## 10. 故障排查

| 症状 | 排查 |
|---|---|
| 发布停在「infra 前置检查」 | `semgravio-{pg,redis,nginx}` 缺失/不健康或 `webnet` 缺失：先起共享 infra（semgravio-infra 的 `deploy.sh`），本服务不代起栈；重跑发布即可 |
| 发布停在「env 全量校验」 | 服务器 `.env.production` 缺变量，或 master key 非法（须 Base64 且解码恰 32 字节）：人工修正后重跑；脚本绝不会自动换 master key「修复」 |
| 发布停在「备份失败」 | pg_dump 未完整产出（残缺文件已自动清理）：看上方 pg_dump 报错，常见为库角色/密码与 env 不一致；确认要跳过用 `SKIP_BACKUP=1`（自担风险） |
| 健康验收超时（默认 180s） | `deploy/server.sh logs`：首启 Flyway 迁移慢属正常（可调 `HEALTH_WAIT_SECONDS`）；DB 连不上 / Redis NOAUTH 会直接抛在启动日志里 |
| 容器反复重启 | compose 健康检查不过 → `deploy/server.sh logs` 看异常栈；`restart: unless-stopped` 会持续拉起 |
| 管理接口一律 401 | admin-console 持有的 apiSecret 与库里不一致（如 master key 换过、seed 已轮换）：取回当前凭证或重新轮换（下一行） |
| 想看当前 apiSecret | bootstrap 端点（无验签，仅内网）：`ssh` 上服务器后 `docker exec semgravio-app-registry curl -s http://localhost:8088/api/app-registry/api-keys/admin-console` |
| 错过日志里的 apiSecret | 日志留存期内 `grep 'admin-console seed'`（§2.3）；超期也不必轮换——上一行 bootstrap 随时取回 |

## 11. 本地排练（不碰真实服务器）

```bash
deploy/rehearsal.sh
```

一次跑完部署面的全部验收：脚本语法/LF 检查 → 部署文档守护（本档与源码不劈叉）→ 发布主链
（真 Maven 打包、首次/重复发布、infra/SSH/env 门禁、master key 校验、Redis requirepass、无端口
暴露、备份、健康失败、admin-console 凭证反馈、secret 不泄漏）→ 运维入口。全链走 ssh/scp/docker
命令替身，**不连真实生产服务器、不改共享 infra 与其他应用数据**。改 `deploy/`、compose 或端点后
跑它回归。
